# 잇데이 앱 조사·수정 결과와 성장 실행안

작성: 2026-09-15 · T-901 · 조사 기준 `259803f` · 작업 가지 `fe/T-901-release-quality`

## 1. 결론

**먼저 ‘만든 것이 사라지지 않고, 보낸 결과를 정확히 알려주는 앱’으로 완성도를 올려야 한다.**
이번 조사에서는 댓글·DM·잇비의 실패 처리와 사진편집 작은 화면 문제를 재현해 수정했다.
T-902 후속 작업에서 DM 예약 카드의 작성값 보존과 개발 도구 보안 갱신까지 추가했다.
T-903에서 사용자 승인 뒤 iPhone·Android 동기화, 시험용 빌드, 켜져 있던 시험 기기 설치까지 통과했다.
새 기능을 계속 늘리기보다 **사진 → 내 말투의 홍보물 → 손님 문의 → 예약 준비**의 연결을 쉽게 만드는 것이 우선이다.

스토어 1위는 보장할 수 없다. 순위의 나라·분야·기간, 현재 설치 수·평점·유지율도 확인하지 못했다.
초기 전략 가정은 **한국의 1인 뷰티샵 원장, 비즈니스 분야에서 경쟁력 확보**다.
목표는 1위라는 표현보다 실제로 시간을 절약하고 다시 사용하는 원장을 늘리는 것으로 관리한다.

**현재 판정: 로컬 수정·검사 완료. 출시 전체 통과 판정은 보류.**
이 문서는 모든 실제 계정·휴대전화·외부 서비스 조합을 검사했다는 보고서가 아니다.

## 5. 사진편집 최적화안

**목표: 사진을 고른 뒤 3단계 안에 쓸 수 있는 홍보물을 완성한다.**

1. **입력 → 결과 선택 → 저장/공유**를 기본 동선으로 유지. 글자·스티커·누끼는 필요한 사람이 펼친다.
2. 이미 있는 자연스러운 뷰티 보정·업종별 스타일 기억·전후 구성·되돌리기를 더 쉽게 발견하게 한다.
   네일 색·피부 질감·속눈썹 선을 바꾸는 과한 보정은 기본 추천에서 제외한다.
3. 7개 업종 × 밝음/어두움 × 세로/가로/전후/여러 장의 고정 사진 세트를 만든다.
   원본·화면·저장본을 나란히 비교해 색·글자·잘림 차이를 확인한다.
4. 큰 사진은 미리보기 크기를 줄이고 원본은 별도 보존한다. 프리셋 미리보기는 작은 이미지로 한 번씩 만들고 재사용한다.
   현재 기능과 겹치는 부분은 측정 후 필요한 곳만 개선한다.
5. 저장/내보내기 실패·앱 백그라운드·공유 취소·사진 권한 거부에서도 작업이 남는지 실기기에서 확인한다.
6. 큰 화면의 왼쪽 메뉴와 안전 영역, 좁은 화면의 키보드·도구칸 겹침, 손잡이 터치 영역을 함께 점검한다.

완료 기준 제안: 12MP 사진 1장의 로컬 미리보기 1초 이내, 저장 95%가 3초 이내,
정해진 중저가 Android에서 조절 중 끊김 최소화, 저장본·재편집 글자/색/위치 일치.
이는 **목표값이며 이번에 측정한 성능이 아니다.**

## 6. 댓글·DM 최적화안

**목표: 답이 필요한 손님을 놓치지 않고, 검토한 답장을 정확히 한 번 보낸다.**

- 기존 통합 문의함을 중심으로 ‘답장 필요 / 확인 필요 / 보내는 중 / 보냄 / 결과 확인 필요’를 구분한다.
- 자동 갱신은 작성 중인 답글을 보호하고, 새 문의가 있으면 ‘새 문의 N건’으로 알려준다.
  다음 단계에서는 목록 전체를 다시 그리지 않고 바뀐 문의만 갱신한다.
- AI 초안의 근거를 샵의 현재 가격표·운영시간·위치로 제한한다. 근거가 없으면 숫자를 만들지 않고 원장에게 질문한다.
- 불만·건강·환불·예약 변경처럼 맥락이 중요한 요청은 사람 검토를 우선한다.
- ‘문의 읽음’과 ‘답장 보냄’을 구분하고, 시간 초과는 미발송으로 단정하지 않는다.
  같은 시도 번호로 서버 상태를 확인한 뒤에만 재전송한다.
- 여러 장치에서 같은 문의를 처리하는 경우를 2개 시험 기기로 확인한다.
- 숨긴 탭과 닫힌 화면은 조회를 쉬고, 실패할수록 조회 간격을 늘린다. 현재 DM 4초·댓글 30초 조회는
  사용자 수와 서버 비용을 함께 측정해 변경한다.
- 현재 댓글 화면은 공개 답글을 맡고 DM은 DM 흐름이 맡는다. ‘댓글 답장’에 DM 자동전송을 새로 붙이지 않는다.

완료 기준 제안: 놓친 실패 문의 0, 연타·응답 유실 시험에서 중복 발송 0,
초안 수정 유실 0, 응답 속도·원장 수정량·답장 후 예약으로 이어진 비율을 함께 관찰.
Meta 제한 시간·권한은 승인된 앱 유형과 최신 공식 문서를 다시 대조해야 한다.
이번 Meta 문서 조회는 실패했으므로 특정 시간 제한을 확인 완료로 적지 않는다.

## 7. 잇비 최적화안

**목표: 원장이 자연스럽게 말해도 대상·수치·실행 여부를 틀리지 않는다.**

1. ‘내일 세 시’, ‘아까 그 손님’, ‘그건 취소하고 네 시’ 같은 이어말하기를 고정 평가 문장에 포함한다.
2. 실행 전 카드는 대상·날짜·수치·할 일을 한 번에 보여준다. 모호하면 해당 항목 하나만 질문한다.
3. 지원하지 않는 일은 가능한 화면이나 수동 초안으로 안내하고, 했다고 말하지 않는다.
4. 말투 학습과 사실 자료를 분리한다. 말투를 잘 흉내 내더라도 가격·예약·서비스 여부는 현재 자료가 우선이다.
5. 예약·회원권·매출은 실행 결과와 화면 합계를 함께 확인한다. 실제 서버의 최종 처리 기록이 성공 기준이다.
6. 확인된 단순 명령은 앱 안에서 바로 처리하고, 자유 문장은 AI로 보낸다.
   같은 질문 중복 요청·불필요하게 긴 대화 전송을 줄인 뒤 답변 품질을 다시 평가한다.

완료 기준 제안: 시험 문장 200개에서 핵심 대상/날짜/수치 정답률 95% 이상,
요청하지 않은 실행 0, 실패를 성공으로 표시 0, 위험 작업 100% 확인 단계 통과.
현재 정답률이나 비용 절감률을 실측했다고 주장하지 않는다.

## 10. 90일 실행 순서

기간은 작업 순서 제안이다. 승인·시험 계정·실기기·개발 인력에 따라 달라진다.

| 기간 | 집중 작업 | 끝났다고 판단하는 조건 |
|---|---|---|
| 1주 | 이번 수정 검토·시험 배포, 개발 도구 보안 업데이트 계획, 스토어 설명 정정 | 새 실패 시나리오·기존 검사 통과, 위험한 미검증 항목 담당자 지정 |
| 2주 | 실기기·시험 서버에서 결제/권한/발송/저장 검증 | 실제 결과 증거가 남음. 막힌 항목을 성공으로 처리하지 않음 |
| 3~4주 | 사진→홍보물 3단계, 문의함 작성본 보존 확대, 잇비 200문장 평가 | 원장 5~10명이 도움 없이 핵심 흐름 완료 |
| 5~8주 | 업종별 스타일 품질·응대 정확도·첫 사용 흐름 개선 | 주차별 유지율·시간 절약 기준값과 개선 확인 |
| 9~12주 | 소개 화면 실험, 성공 사례, 업종별 유입 경로 확대 | 설치 후 핵심 기능 사용과 유지가 함께 개선 |

1위 도전을 확대할 시점은 ‘오류가 적다’만으로 정하지 않는다.
**사용자가 매주 돌아오고, 시간을 절약했으며, 주변 원장에게 추천할 이유를 말할 수 있을 때** 확장한다.

## 11. 파일 크기/분리 판단

기존 큰 실행 파일 3개는 공통 처리와 해당 분기만 수정했다. 이번 기능을 새 전역 모듈로 분리하면
로드 순서 의존성이 늘어나므로 같은 파일의 작은 함수로 유지했다. 새 함수는 50줄 이하다.
새 검사 파일 3개와 외부 차단 실행 도구는 각각 500줄 이하이며, 제품의 기존 로드 순서는 바꾸지 않았다.
기존 큰 파일의 전체 재구성은 이번 안정성 수정과 분리한다.
