# T-912 로그인 정보 탈취 경로 차단

## 문제

1. 인스타 연동용 1회용 표 요청에 로그인 확인값이 빠져 항상 실패하고, 옛 방식인 주소 속 로그인 값으로 내려간다.
2. iPhone·Android 안전 저장소는 브라우저가 읽지 못하는 불러오기 방식을 써서 실제 기기에서 꺼질 수 있다.
3. 주소의 `securetoken=0` 한 번으로 휴대폰 안전 저장을 계속 끌 수 있다.
4. 소셜 로그인 복귀 코드가 공통 안전 저장 함수를 거치지 않고 브라우저 저장소에 직접 쓴다.
5. 웹 로그인 복귀가 스테이징 로그인 값을 다른 환경 칸에도 복제하고, 페르소나 화면에 직접 저장소 읽기 우회가 남아 있다.

## 위험

- 주소에 들어간 로그인 값은 서버 접속 기록·브라우저 기록·공유 화면 등에 남을 수 있다.
- 휴대폰에서 로그인 값이 일반 브라우저 저장소에 남으면 화면 코드가 뚫렸을 때 함께 빠질 수 있다.

## 범위

- `app-instagram.js`: 1회용 표 요청에 로그인 확인값 추가, 주소 속 로그인 값 대체 경로 제거.
- `app-core.js`: 휴대폰 내장 연결 방식으로 안전 저장소 사용, 주소/브라우저 저장값으로 끄는 기능 제거, 휴대폰에서 안전 저장 실패 시 일반 저장소로 내려가지 않음.
- `app-oauth-return.js`: 소셜 로그인 결과를 공통 저장 함수로만 저장.
- `oauth-return.html`, `app-persona-survey.js`: 다른 환경 로그인 칸 복제와 직접 읽기 우회 제거, 로그인 복귀 주소 전달 차단.
- `__tests__/auth-token-theft-guards-2026-09-22.test.js`: 위 네 경로가 다시 생기면 실패.
- `.ai/APP_FEATURE_INDEX.md`: 로그인·인스타 연동 보안 상태 갱신.

## 제외

- 운영 배포, 실제 고객 데이터 조회, 실제 계정 로그인, 앱 심사 제출물 변경.
- 웹 로그인 값을 서버 전용 쿠키로 바꾸는 큰 구조 변경은 서버와 함께 별도 진행.
- 웹판의 고객 목록·예약·매출 임시 저장을 짧은 세션 저장으로 옮기고, 오프라인 고객 입력을 안전하게 보관하는 작업은 데이터 유실 회귀 검증이 필요해 별도 진행.

## 승인

사용자가 2026-09-22에 로그인 정보와 고객 정보 탈취 방지를 강하게 요청해 이 안전 수정과 로컬 검증을 승인했다.
