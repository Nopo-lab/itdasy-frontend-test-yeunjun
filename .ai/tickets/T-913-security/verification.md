# T-913 보안 보강 검증 — 2026-09-22

## 승인과 제외

사용자: “응 해결해. 심사 전 웹전환 제외하고 나머지는 끝내둬.”
보안 수정과 정상 배포를 진행한다. 앱 내장 전환, 웹 폐쇄, 저장소 비공개 전환,
스토어 재제출은 하지 않는다. 운영 고객 DB 직접 조회도 하지 않는다.

## 구현

- 휴대폰 로그인은 안전 저장 실패 시 중단. 늦은 읽기/쓰기/로그아웃 경합과 앱 재시작을 방어.
- 인스타 연동 주소의 장기 로그인값 제거. 서버도 짧은 1회용 표만 수락.
- 관리자 실시간 연결은 주소 대신 첫 메시지로 인증하고, 최대 30초마다 권한 재검증.
- 비밀번호 재설정은 DB 기록과 비밀번호 변경을 함께 확정하여 동시 재사용 차단.
- 1회용 사용 기록 저장 실패 시 통과시키지 않고 일시 실패로 처리.
- 로그인값의 용도·만료·계정 존재·활성 상태 검사. 갱신으로 최초 로그인 24시간을 넘길 수 없음.
  별도 회전형 갱신값/기기별 세션 구조를 완성한 것은 아님.
- 고객/매출/홈/대시보드 조회 사본은 창 세션 저장. 오래된 영구 조회 사본만 정리.
  다른 창의 계정 변경 및 늦게 도착한 이전 계정 응답을 차단.
- 공개 시험 스크립트·심사 문서에서 비밀번호 제거. 공개 웹 산출물에서 output/검사/coverage 제외.
- 공개 DB 스키마는 외부 API 역할의 표·뷰·함수·시퀀스 접근 차단(0069).
  사진 저장소 스키마는 변경하지 않는다. 백엔드 DB 소유자 권한은 여전히 별도 위험 경계.

## 완료로 표시하면 안 되는 항목

1. 심사 계정 비밀번호: 공개 이력 존재. App Store Connect 편집 가능 확인했으나 계정은 비밀번호 변경 차단 상태.
   서버 담당자 변경과 스토어 비공개 로그인 정보·메모 동시 갱신 필요. 심사 메시지에도 옛 값이 있어 담당자 안내 필요.
2. 서버·DB·외부 서비스 키 교체: 새 Secret Manager 버전 날짜만으로 실제 값 폐기를 증명할 수 없음.
   암호화 키는 기존 인스타 연결정보 이관 없이 교체하면 복호화 불가. 이번에 교체했다고 보고하지 않음.
3. 웹 로그인값은 여전히 브라우저 일반 저장. 서버 전용 쿠키는 동일 사이트 제공 구조/로그인 계약 변경 필요.
4. 미전송 고객 원본·오프라인 초안은 자료 유실 방지를 위해 보존. 암호화 전환은 아직 안 됨.
5. 고객 DB 항목별 추가 암호화와 강한 화면 삽입 차단 정책, 별도 회전형 갱신값/기기별 세션은 미완료.
6. 구글·네이버·카카오·애플·인스타 실제 계정 연결 전 과정, 실제 단말 및 독립 침투 검증은 별도 확인 필요.

## 파일 크기/분리 판단

새 DB 권한 유틸리티·변경 파일·동작 검사 파일은 분리한다. 기존 큰 파일은 로그인 저장과
조회 사본 처리 연결 부분만 변경했다. 고객/홈/매출의 전면 재작성이나 스크립트 순서 변경 없음.
파일 목록은 해당 보안 커밋의 `git show --stat`로 확정한다. 관련 없는 사업계획/이미지 자료는 제외.
