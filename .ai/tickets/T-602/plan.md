# T-602 구현 계획

1. 기존 고객 상세 안에 인라인 고객 케어 패널. 모바일/PC 동일 흐름, 폼은 한 번에 하나만. 실데이터 없음/실패/로딩 구분.
2. 시술 기록 기존 저장 구조 재사용. 과거 내용 복사는 시술명·메모만, 새 날짜·새 사진 분리. 등록·수정·재접속 및 실패 시 입력 유지.
3. 다음 관리일의 수동 지정·해제를 별도 상태로 보존. 고객 목록/리터치/예약 완료 경로와 동기화. 한국 날짜 기준.
4. 소개 고객은 같은 샵 고객 간 연결. 자기 자신·타샵 관계 금지. 삭제/합치기/이름 변경 처리.
5. 새 서버 계약은 additive. 기존 고객 데이터·클라이언트 호환 유지. 서버 먼저 배포 후 새 프론트.
6. 의미 있는 자동검사와 로컬 서버/브라우저 통합검사, 모바일·PC 화면, 실패/중복/권한/재접속 확인. 실제 고객 데이터로 쓰기 테스트하지 않음.
7. 독립 검토 후 티켓 번호 포함 커밋. 양쪽 허용 저장소 main에 검증된 변경만 반영·푸시, 배포 확인.

권한: 사용자 이번 요청으로 세 기능 개발·개인정보 관련 저장 구조·검증·커밋·푸시 승인. 추가 확인 불필요. 이 승인은 실제 고객 대상 연락 발송 승인으로 해석하지 않음.

파일 크기/분리 판단: 신규 UI data/view/controller, 서버 정책/라우터/모델을 독립 검증 단위로 분리. 기존 큰 파일은 연결부 최소 수정. 신규 파일 500줄 이하 목표.
